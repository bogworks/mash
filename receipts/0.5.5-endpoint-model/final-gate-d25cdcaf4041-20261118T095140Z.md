## Pass 1: security

## Dimension 7 — Security assessment

**Untrusted actors and reach.** An endpoint holding a user credential can send mail, prompts and status within its owner and can answer reply inboxes within that owner. The revised permission set confines peer subjects and reply inboxes to a literal owner token ([permissions.go](internal/admin/permissions.go:29)). Endpoint connections use that credential’s private inbox prefix ([endpoint.go](internal/endpoint/endpoint.go:379)). An administrator with account keys has broader provisioning and revocation authority; the contract deliberately keeps those keys on the mashctl hosts.

**Evidence.** The code writes endpoint seeds and credentials with mode 0600 and checks that a seed matches its JWT before assembling credentials. Negative tests cover invalid or reused keys, cross-owner mail and prompt attempts, forged and replayed discovery replies, and revoked credentials. The later [AT-003 record](pages/evidence/docs__evidence__2026-11-17-0-5-5-live-runs__record-at003-8fa36b8.md) and [AT-005 record](pages/evidence/docs__evidence__2026-11-17-0-5-5-live-runs__record-at005-bc96b27.md) report server permission violations for the cross-owner reply attacks. I inspected the records and code read-only; I did not rerun tests.

**Concern to investigate — remote endpoint transport.** Endpoint TLS enforcement is off by default: [operations.md](docs/operations.md:19) says a remote plain NATS connection is allowed unless `require_tls` is set. The AT-005 refusal exercised the setting enabled. A deployment that omits it could expose endpoint credentials over the connection. This is an existing, documented limit, and [ADR 0059](pages/decisions/docs__decisions__0059-mashctl-checks-who-issued-the-account-jwt-carries-only-its-own-signing-keys-and-requires-tls-for-admin-connections.md) explicitly leaves endpoint connections unchanged. **Severity:** potentially high. **Certainty:** high about the default; deployment exposure depends on configuration. Confirm that remote setup instructions reliably enable TLS enforcement.

**Blocking gate finding — review mode cannot be attested.** The [gate standard](pages/gate-standard/final-gate__STANDARD.md) requires the security pass record to name the Codex version, model, and Daybreak setting; without the required mode it is a gap. This review invocation provides no verifiable Codex version or Daybreak status. Consequently this pass cannot establish that it ran in the required security mode, regardless of its code findings. Resolve it with an attested rerun on the required model and Codex version with Daybreak on. **Severity:** gate blocking. **Certainty:** high that the attestation is unavailable here; unknown whether Daybreak was active.

RATING 7 gap | Security boundaries and negative tests have supporting evidence, but this pass lacks the required model, Codex-version and Daybreak attestation.
