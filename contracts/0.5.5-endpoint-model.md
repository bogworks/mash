## 1. Intent

### Problem

mash has two address forms. Endpoints made by `mashctl add` carry the fixed token `cc` in the first subject slot, have no
group level, and get credentials minted on the mashctl host, so a remote endpoint's private key is copied by hand. The
maintainer has ruled: there are no legacy endpoints; the address is owner, then group, then instance; every endpoint
names its group; and 0.5.5 is a hard cut.

### Desired outcome

mash 0.5.5 knows one endpoint model and nothing else. Every endpoint has the address `<owner>.<group>.<instance>`, is
made by `mashctl endpoint create` in a canonical form or a shortcut, and can have its private key made on its own
machine so that nothing secret travels. The old form is gone from the code: 0.5.5 does not read, convert or tolerate old
records, addresses or credentials.

### Motivation

The policy release builds on this model (standing order 15). No one uses mash yet, so a hard cut costs nothing that a
soft cut would save (maintainer, 2026-11-17).

### Success measures

- AT-001 to AT-004 pass live, with transcripts.
- A search of the source, tests and docs for the old form (`cc` slot, `agent_token`, `MASH_AGENT_TOKEN`, `mashctl add`,
  legacy parsers) finds it only in the release notes and in the messages of REQ-009.

### Non-goals

- Moving existing endpoints. That is a one-time operator script outside mash, owned by operations, with its own
  rollback plan; this contract names that it exists and nothing more (section 7).
- Policy of any kind: list sets, narrowing grants, the `policy` verb (the release after).
- High availability, replicas, write quorums (standing order 14).
- More than one NATS server, TLS, or several mashctl hosts: these are not tested and the release notes say so.
- Renaming the other mashctl commands (`init`, `list`, `audit`, `adopt`, `issued`, `inbox`, `limits`, `suspend`,
  `label`) under nouns.
- Mail that waits in an idle mailbox (decision 249): the next contract.

## 2. Actors and journeys

### Actors

- ACT-001: a solo developer on one machine, with nothing above mash installed. Goal: two Claude Code sessions that mail
  each other. Authority: owns the machine, the local NATS server and the account keys. Context: `mashctl init --local`.
- ACT-002: an agent driving `mashctl` through `--json` and exit codes.
- ACT-003: an endpoint that runs on a machine other than the mashctl host.

### Primary journeys

- JRN-001 (ACT-001): install mash and mashctl as the README says; `mashctl init --local --owner alice --start`;
  `mashctl endpoint create alice/dev/design` and `mashctl endpoint create alice/dev/review`; install the plugin; start
  two sessions with `MASH_GROUP=dev` and `MASH_NAME=design` or `review`; mail each way; stop the server.
- JRN-002 (ACT-003): on the endpoint's machine `mash credential key --out design.seed` prints the public half; the
  public half reaches the mashctl host as a file; `mashctl endpoint create alice/dev/design --public-key design.pub`
  writes `alice.dev.design.jwt`; the JWT file goes back; `mash credential install` makes the creds file; the session
  connects.

### Exceptional journeys

- JRN-003: a key is revoked (`endpoint delete`, `endpoint reissue`, `credential revoke`); the session using it is
  dropped and cannot reconnect.
- JRN-004: a group is missing on any command or at session start; a readable refusal names what to add.
- JRN-005: someone types `mashctl add`, `mashctl reissue` or `mashctl retire`; exit 2 names the replacement.
- JRN-006: a `create`, `reissue` or `delete` run is killed half way; the same command run again completes it.

## 3. Behavioral requirements

### REQ-001: one address form

- Source: Confirmed (standing orders 10, 15)
- Trigger or precondition: any endpoint is created, addressed or connected.
- MUST: the address is three tokens, owner, group, instance, each matching `[a-z][a-z0-9-]*`, 1 to 32 characters, no
  `--`, no trailing dash; the dotted address is at most 64 characters. Subjects are
  `agents.<verb>.<owner>.<group>.<instance>`. The name rule file is read per token with keys `owner`, `group`,
  `instance`.
- Observable postcondition: every subject an endpoint publishes or subscribes to has the owner in slot 1.
- Failure behavior: a token that breaks the rule is refused `name_invalid` or `name_rule`, exit 1, and nothing is written.
- Acceptance: AT-001, AT-003

### REQ-002: every endpoint names its group

- Source: Confirmed (maintainer, 2026-11-17: no group, no endpoint)
- Trigger or precondition: `endpoint create`, or a session start, without a group.
- MUST: there is no default group. A command without a group is refused with code `group_missing`, exit 2, and a message
  naming both ways to give one (`--group dev`, `alice/dev/design`). A session started without `MASH_GROUP` (or the
  matching config key) stops at once with a message naming `MASH_GROUP`.
- Observable postcondition: no record, subject, stream or file is created with an implied group.
- Failure behavior: as above; nothing is written.
- Acceptance: AT-003

### REQ-003: `mashctl endpoint create`

- Source: Confirmed for the two forms (standing order 15); Derived for the rest (#729 section 2)
- Trigger or precondition: the account key is present on the mashctl host.
- MUST: `--owner O --group G --name N` and the shortcut `O/G/N` mean the same; a single token is the instance and needs
  `--group`; the owner defaults to the configured owner; a two-token shortcut is refused as ambiguous (exit 2); a form
  that mixes flags and shortcut is refused unless they agree. Output to stdout: text by default, or one JSON document
  (`schema` `mashctl-endpoint@1`, fields `owner`, `group`, `instance`, `address`, `key`, `outcome`, `creds`,
  `next_steps`, `refusal`) with `--json`. `--dry-run` writes nothing. A failure at any step undoes earlier steps.
- Observable postcondition: a directory record, an inbox stream and consumer, an issue record, and either a creds file
  (no public key given, DEC-002) or a JWT file (REQ-004).
- Failure behavior: refusal codes `name_invalid`, `name_rule`, `group_missing`, `address_taken`, `key_retired`,
  `creds_exists`, `no_account_key`, exit 1 (exit 2 for usage); a server failure is `error`, exit 6.
- Acceptance: AT-001, AT-003, AT-004

### REQ-004: the endpoint can make its own key

- Source: Confirmed (maintainer, 2026-11-17: "Made locally makes sense to me")
- Trigger or precondition: an endpoint runs on a machine other than the mashctl host, or the operator chooses this path.
- MUST: `mash credential key --out FILE` makes a user key pair on the endpoint's machine, writes the seed to FILE with
  mode 0600, refuses to overwrite, and prints only the public key. `mashctl endpoint create ADDRESS --public-key FILE`
  signs user claims for that public key with the account signing key, records the issue (public key, address, owner,
  issued time; no seed, no JWT), and writes the JWT to a file. `mash credential install --seed FILE --jwt FILE --out CREDS`
  assembles the creds file on the endpoint's machine. `key` and `install` need no NATS connection and no account keys.
- Observable postcondition: the mashctl host holds no seed for that endpoint; the endpoint connects with the assembled
  creds file.
- Failure behavior: a malformed public key, or a public key already issued at another address, is refused, exit 1.
- Acceptance: AT-002

### REQ-005: what a credential may reach

- Source: Confirmed (standing order 12, wide open); Derived for the exact set (#728 section 1.4)
- Trigger or precondition: any credential is signed.
- MUST: for endpoint `O.G.I` with flat key `F`, publish is allowed on `agents.mail.O.*.*`, `agents.prompt.O.*.*`,
  `agents.status.O.*.*`, its own `agents.hb.O.G.I`, and the fixed lines it has in 0.5.0 (reply inboxes, service
  discovery, its own stream and consumer, the directory read, its own lease key); subscribe is allowed on `_INBOX.F.>`,
  its own `agents.prompt.O.G.I` and `agents.status.O.G.I`, service discovery, and `agents.hb.O.*.*`. The owner is a
  literal token in every peer line. A grant with a wildcard in the owner slot is refused.
- Observable postcondition: `mash admin permissions O.G.I` prints exactly this set.
- Acceptance: AT-001, AT-004

### REQ-006: SAP metadata and the stated departure

- Source: Confirmed (standing orders 5, 10)
- MUST: the service metadata keeps `agent` as the real harness (`claude-code`) and adds `owner`, `group`, `instance`. The
  README's SAP section and `docs/sap.md` state that mash departs from SAP's SHOULD for slot 1 and that discovery by a
  wildcard on the harness slot finds no mash endpoint, while discovery by service name does. No SAP protocol change and
  no SDK divergence.
- Acceptance: AT-001 (metadata read); inspection of the docs

### REQ-007: what is keyed by the address

- Source: Derived (#728 section 1.3)
- MUST: the directory record, inbox stream (`inbox-<flat>`), lease, issue record and retired-key ledger are keyed by the
  flat key `<owner>_<group>_<instance>`; the creds file is `<owner>.<group>.<instance>.creds`. Every deleted endpoint's
  flat key is burned.
- Acceptance: AT-001

### REQ-008: how a session names its endpoint

- Source: Derived (#729 section 8)
- MUST: a session reads `MASH_OWNER` (or the configured owner), `MASH_GROUP` and `MASH_NAME`; the three make the address.
- Failure behavior: a missing group is REQ-002; a missing name keeps 0.5.0's behaviour.
- Acceptance: AT-001, AT-003

### REQ-009: the old form is gone

- Source: Confirmed (standing orders 11, 15; maintainer, 2026-11-17, the hard cut)
- MUST: `mashctl add`, `mashctl reissue`, `mashctl retire`, the `cc` address form, `agent_token`, `MASH_AGENT_TOKEN`, the
  legacy parsers and every code path that reads an old record are removed. The three old commands run nothing, exit 2
  and name their replacement (CLI standard rule 13). No aliases. 0.5.5 does not read, convert or tolerate old records,
  addresses or credentials.
- Acceptance: AT-003; the source search of section 1

### REQ-010: reissue, delete, list, show

- Source: Derived (#729 section 4)
- MUST: `mashctl endpoint reissue ADDRESS` (and `--all --yes`, `--changed --yes`) gives an endpoint a fresh credential
  and revokes the old; `mashctl endpoint delete ADDRESS` revokes the key, removes the record and inbox, and renames the
  creds file `.retired-<time>` (or removes it with `--delete-creds`); `list` and `show` change nothing. Each takes
  `--json`; the changing ones take `--dry-run`. Exit codes follow ADR 0144.
- Acceptance: AT-001, AT-004

### REQ-011: what a revoked session sees

- Source: Derived (core, 2026-11-17)
- MUST: revoking a key updates the account JWT on every server mashctl knows; the server closes that key's live
  connections and refuses reconnects as not authorized; `mash status` reports the authorization failure.
- Acceptance: AT-001

### REQ-012: documentation

- Source: Derived
- MUST: the README quick start follows JRN-001 and names a group; the README states the SAP departure; `docs/mashctl.md`
  covers the `endpoint` commands and the credential commands; the release notes lead with the hard cut (0.5.5 does not
  work with endpoints made by 0.5.0: make new ones) and say what is not tested.
- Acceptance: inspection; the maintainer follows the README (validation)

### REQ-013: the command-line standard

- Source: Confirmed (standing order 13); Proposed for the one verb (DEC-003)
- MUST: the `endpoint` commands conform to the CLI standard 1.0.1 (noun, verb, at most one positional, `--json` on
  reads, `--dry-run` on changes, readable refusals). `reissue` is added to the standard's verb table.
- Acceptance: the command-tree test for the `endpoint` noun (AT-004)

## 4. System boundaries

### BND-001: mash and anything above it

- Charter or seam page: none exists (finding F-1); standing orders 1, 2, 6, 8 apply.
- Owned responsibility: endpoints, their addresses, credentials and mailboxes.
- Allowed interactions: anyone may run `mashctl` and `mash` and read their JSON.
- Prohibited interactions and effects: no requirement, flag, subject, key, field, error text or test names a layer
  above mash.
- Enforcement: the forbidden-word test that exists today, extended to the new code.
- Approval to change: the maintainer.

### BND-002: SAP

- Charter or seam page: none; standing order 5.
- Owned responsibility: what mash puts in the three slots.
- Prohibited: any change to the SAP protocol or divergence from the SAP Go SDK.
- Enforcement: the SDK compatibility gate that exists today.
- Approval to change: none possible (standing order 5).

### BND-003: the NATS server

- Owned responsibility: mash uses account JWTs, user JWTs and the account revocation list as in 0.5.0.
- Prohibited: changes to server configuration beyond what `init --local` writes today.
- Enforcement: prose.

### What this component must not know

- Standing orders checked: `standing-orders/mash.md` as of 2026-11-17. Conflicts: order 15 says "one command moves
  existing endpoints over"; the maintainer's ruling of 2026-11-17 (no move command, a hard cut) replaces that clause
  (F-2).
- Concepts of layers above that appear nowhere in a requirement, flag, subject, key, field, error text or test: range,
  herd, lane, wrangler, homerange, rangehand, lane roles, labels and rule languages of any layer above it, trailboss,
  any herd's name.

### Existing behavior to preserve

- Mail delivery, sender signing and the trust labels, hook and channel delivery, the plugin's tools.
- `mashctl init --local` and its flags; the commands not named in REQ-009 and REQ-010 keep their 0.5.0 spellings.
- The several-servers flags (`--servers`, `--sys-creds`) on every command that writes.

## 5. Invariants and constraints

### INV-001: no secret leaves where it belongs

No seed or creds file contents are printed, logged, mailed or stored by mashctl in the REQ-004 path. No command prints
a seed. `endpoint create --public-key` without `--out` prints the JWT, which is not secret.

### INV-002: no reach across owners

No credential signed by 0.5.5 can publish or subscribe on another owner's subjects.

### Security, reliability, compatibility, performance

- NFR-001: a killed run of `endpoint create`, `reissue` or `delete` leaves either nothing or a state that the same
  command, run again, completes.
- NFR-002: tested on one NATS server made by `init --local`; the release notes say multi-server and TLS are not tested.
- NFR-003: build size: core 10.5 person-days (address and subjects 2, permissions and keyed storage 2.5, removal of the
  old form 3, REQ-004 1.5, live proof, docs and release notes 1.5); ctl 8 (endpoint noun 3, credential key and install
  1, removals 1, goldens and command-tree test 1.5, docs 1.5), after core's model lands. 18.5 in all, down from 26.

## 6. Acceptance contract

All runs: one machine, one local NATS server from `mashctl init --local`, scratch homes, no tool above mash installed,
no state from any earlier mash version.

### AT-001: the solo developer, standalone

Given a fresh scratch home, when the README quick start is followed (`init --local --owner alice`, `endpoint create
alice/dev/design`, `endpoint create alice/dev/review`, plugin, two sessions with `MASH_GROUP=dev`), then mail goes each
way verified, `endpoint list --json` shows both with `group` `dev`, the service metadata shows `agent` `claude-code`
and the three parts, `mash admin permissions alice.dev.design` prints REQ-005's set, and after `endpoint delete
alice/dev/review` the review session's connection is closed, a reconnect is refused, and `mash status` says why.

### AT-002: the endpoint makes its key

Given two scratch homes A (mashctl host) and B (endpoint), when B runs `mash credential key`, A runs `endpoint create
alice/dev/design --public-key`, and B runs `mash credential install` and connects, then the endpoint mails a peer, and
a search of all captured output and of A's home for the seed finds nothing.

### AT-003: refusals

Each of these is refused with the stated exit code and a message that names what to type: `endpoint create design` with
no group (2); `endpoint create alice/design` (2); a token that breaks REQ-001 (1); a session with no `MASH_GROUP`;
`mashctl add`, `mashctl reissue`, `mashctl retire` (2).

### AT-004: the command contract

Golden text and JSON for `endpoint create` (planned, created, each refusal), `reissue`, `delete`, `list`, `show` and the
removed-command messages. `--dry-run` leaves the directory, the issue record and the config directory byte-identical. The
command-tree test walks the `endpoint` noun (at most one positional, `--json` valid, `--dry-run` changes nothing, a bad
flag exits 2, `--help` has an example). A killed `create` run, run again, completes (NFR-001).

## 7. Assumptions and open decisions

### Confirmed assumptions

- No one uses mash yet besides the maintainer (maintainer, 2026-11-16 and 2026-11-17).
- The maintainer's own endpoints are moved by a one-time operator script outside mash, owned by operations, with its own
  rollback plan (old binary, old credentials and old state kept untouched until the operator says everything is
  healthy). Because 0.5.5 does not tolerate old state, that script gives 0.5.5 a deployment with no old records in it
  (for example, a fresh local server, account and buckets), leaving the old deployment intact for rollback. This is a
  constraint on the script, stated here so that no requirement grows to cope with old state.

### Unresolved decisions

- DEC-002 [not blocking]: does `endpoint create` without `--public-key` (mashctl makes the key, as `add` did) stay, for
  endpoints on the mashctl host? Recommended: yes, both forms. Owner: the maintainer.
- DEC-003 [not blocking]: `reissue` added to the CLI standard's verb table. Owner: the maintainer; the planner edits the
  standard.

### Closed decisions

- DEC-001: closed 2026-11-17. No move command; a hard cut (maintainer).

### Delegated to the herd

- Flag spellings within the CLI standard.
- JSON field order, refusal wording, test layout, the ADR amendments listed in #728.

### Changes that need approval

- Any change to SAP subjects beyond REQ-001, to the permission set in REQ-005, or any new default: the maintainer.
- Any code, flag or command that exists to handle old state: the maintainer (expected answer: no).

### Findings for the planner

- F-1: mash has no charter and no seam pages; this contract cites the standing orders instead.
- F-2: standing order 15's clause "one command moves existing endpoints over" is replaced by the hard-cut ruling.
