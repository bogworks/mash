`mash status --detail --json`'s `reason_code` is now set where each failure is found, not guessed from the words of the reason: a plain server address or a server that offers no TLS is `server_no_tls`, creds that belong to another endpoint are `creds_refused`, a refused client certificate is `server_untrusted`, and an endpoint whose directory record is gone is `endpoint_deleted`. At a shell, `session` is read whatever the sign-in said, and a serve that stops holding its endpoint removes its record; `storage` is decided by trying the folder, not from a record. `mash version --json` and the `version` tool carry the whole 40-character commit; the text shows seven. `mash join` compares a join file's certificate authority with the one `config.json`'s `ca` names, and refuses one where the folder has none and already holds an endpoint. `mash doctor`'s delivery rows read: `warn  hooks have not run in this session yet; they run with the first prompt or tool call` (so `--strict` exits 1 until the first hook runs) and `FAIL  hooks are not delivering mail to this session; restart the session after reinstalling`, with the hint `claude plugin install mash@mash`.
