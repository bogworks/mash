`mashctl policy apply`, `add` and `reissue` now measure each sender's user JWT inside the full CONNECT line, and each account JWT, against the limit of every server (`max_control_line`, and the account JWT cap or `max_payload`, asked of each server through the system account), and refuse the whole list set before anything is signed or pushed when one does not fit, naming the sender or account, its size, the limit and the server. This replaces the fixed 3,750 byte user JWT limit and the 135 tag warning. A server that does not answer is not assumed: pass `--max-control-line BYTES` or set `MASH_MAX_CONTROL_LINE`. `policy check` and `policy show --budget` measure against the default server limit. The check is also built against the list set compile (`listset.MeasureCompiled`, not yet wired into apply, which keeps the measured check on the zone compile until zones are removed). The limit is documented as a measured table by owner part and name length, never as a count, with worked examples ([ADR 0099](docs/decisions/0099-a-credential-is-refused-on-its-measured-size-against-every-servers-limit.md)).
