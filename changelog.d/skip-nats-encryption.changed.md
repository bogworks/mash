Turning encryption off now has one name, and the old one stops working. To allow a plain-text `nats://` or `ws://` connection, for `mash` and `mashctl` alike, set `MASH_DANGEROUSLY_SKIP_NATS_ENCRYPTION=1` in the environment; there is no flag and no `config.json` key. While it is set, every command prints `warning: encryption to the server is OFF (MASH_DANGEROUSLY_SKIP_NATS_ENCRYPTION is set)` on stderr once at the start. `MASH_INSECURE_PLAINTEXT` and the `insecure_plaintext` key in `config.json` are no longer read: each is refused with an error that names the new variable.
