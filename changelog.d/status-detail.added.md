`mash status --detail` (and the `status` tool with `detail`) says whether mail will reach the session: `holds endpoint`, `hooks` (`ran`, `not_run`, `suspected`, `degraded` or `refused`) and `storage`; with `--json` it adds `reason_code` (a fixed word beside the reason) and `session`. At a shell on the session's own machine it reads the same state from what the session's serve recorded, so the command and the tool agree; with no session there it says `session: none`. `mash doctor`'s `delivery` row now also reports the hooks: a warning while they have not run in the session yet, a failure when they are not delivering mail. The usual `status` line and `--json` object are unchanged.
