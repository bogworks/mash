`mashctl policy reconcile` is the dry run of the first-list-set reconcile of an adopted account (AT-015). After the first list set is applied it prints the plan and changes nothing: each signing key that is not one of the list set's scoped keys and is still in the account JWT (a finding), or with `--listset FILE` before the first apply each one the apply removes; the recorded issued users whose sender is not in the list set and the connected keys that are neither recorded, exempt nor issued under the list set, each with the sender or connection (user name, host, server) and the reason; and every finding it cannot prove, with the status `reconciled: nothing to do`, `reconciled: N actions` or `reconciled: partial (N unknown)` (`--json` gives the same plan). A recorded key is revoked only when its issue-record history is complete (ADR 0115) and not future-dated, a connected key signed by one of the list set's scoped keys is never revoked as untracked, and a key with no record is untracked only when the issue bucket proves no record was lost. The command exits 1 when the admin user or a connected exempt user is signed by a signing key that does not stay. `--yes` is refused with `no signer configured: run without --yes to see the plan`; the executor (`internal/reconcile`) is built and tested with a test signer, so wiring it is one call. `issued check` and the reconcile share one gathering of the connected keys, and CONNZ now also reports each connection's host and its user JWT's name and `iat`.
