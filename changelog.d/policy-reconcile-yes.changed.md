`mashctl policy reconcile --yes --plan DIGEST` now executes the plan of the dry run (AT-015); it no longer refuses with `no signer configured`. The dry run ends with `plan: sha256:<hex>` (`plan_digest` in `--json`), the SHA-256 of the plan's canonical JSON without its times and connection details, and a revoking plan says `run again with --yes --plan sha256:... to revoke`. `--yes` without `--plan`, or with `--listset` or `--json`, exits 2. It takes the account lock and the ledger lease, computes the plan again and refuses (`the plan changed since the dry run: run it again`) when its digest is not the one given, then revokes each planned key with the operator key, pushes and gates the JWT, commits it as the JWT in force and marks the recorded keys revoked, printing `revoked KEY: REASON` per key and `reconciled: N revoked`; any refusal exits 1 with nothing changed. The policy signer (`policyserve.Issuer`) can now drop the account JWT's non-mash signing keys instead of refusing: when it is given the admin user's issuer and a source of the connected exempt users' issuers, it drops them once `admin.CheckIssuersKept` shows the admin user and those users stay under a kept key (the account key, an owner group key of the key store, or a key of the list set), and refuses with that check's error otherwise; without them it refuses as before, so `policy serve` keeps refusing until it sets them.
