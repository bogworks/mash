**Every mash connection now requires TLS, including to localhost.** `mashctl init --local` makes a certificate authority and a server certificate and writes a `tls://` URL and `tls_ca` into `config.json`, so the quick start runs over TLS with no extra setting. A plain `nats://` or `ws://` URL is refused before mash connects, with exit code 2, naming the fix: use a `tls://` URL with the server's certificate (`tls_ca` for a private CA). The one override is `insecure_plaintext` (`MASH_INSECURE_PLAINTEXT=1`), for a throwaway server in a test; each command then prints a warning, because plain text lets anyone on the network read mail and obtain signatures. The settings `insecure_loopback` and `require_tls` (`MASH_INSECURE_LOOPBACK`, `MASH_REQUIRE_TLS`) are gone.
