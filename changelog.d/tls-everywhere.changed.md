**Every `mash` and `mashctl` connection now requires TLS, loopback included.** A plain `nats://` URL (or one with no scheme, or `ws://`) is refused before any connection is made, unless `insecure_plaintext` (`MASH_INSECURE_PLAINTEXT=1`) is set; with it set, mash connects, prints a warning on standard error and shows it in `mash status`. Use a `tls://` URL, and `tls_ca` for a private certificate authority. `mashctl init --local` makes its own certificate authority and runs its server with TLS only, so the quick start needs no override. `insecure_loopback` and `require_tls` (`MASH_INSECURE_LOOPBACK`, `MASH_REQUIRE_TLS`) are removed and are not read ([ADR 0146](docs/decisions/0146-every-mash-and-mashctl-connection-requires-tls-loopback-included-and-one-override-insecure-plaintext-allows-plain-text.md)).
