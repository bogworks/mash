`mashctl add` and `mashctl reissue` now refuse while a list set is in force, before they make any key, directory record or creds file, and name the governed path: `a list set is in force (generation N): add would mint an owner-wide credential the list set does not govern; get a governed one with: mashctl credential issue --address OWNER.NAME --endpoint cc.OWNER.NAME --public-key <the endpoint's public key>; nothing was changed`. The credential `add` mints is owner-wide and carries no endpoint tag, so a list set never restricted it. An endpoint made by `add` is now governed in place, with no migration and no moved mail: its endpoint tag is its name, and the credential engine signs one for the public key the endpoint made only while the directory holds a legacy record of that name under the same owner. The `mashctl credential issue` command itself is not part of this release; this is the engine and the refusal
([ADR 0138](docs/decisions/0138-a-legacy-endpoint-is-governed-in-place-its-endpoint-tag-is-its-name-and-add-refuses-under-an-applied-list-set.md)).
