The policy file is gone. Endpoints are now declared in the directory by `mashctl add`, and every endpoint's permissions are the owner-line set `admin.Permissions(owner, name)`, so nothing reads a file to decide who an endpoint is or what it may do ([ADR 0091](docs/decisions/0091-there-are-no-zones-mail-keeps-the-five-token-subject-and-the-address-is-the-fence.md)).
`mashctl add NAME` mints the user, records it in the issue record, provisions the directory record and inbox and writes the creds file, and refuses a name the directory already holds; its `--describe` and `--cap` set the record's description and capabilities. `mashctl reissue` takes names directly or `--all` (every endpoint in the directory), and `--changed` still compares each creds file with what a mint issues now; `mashctl retire` and `mashctl label`/`unlabel` act on the directory record, and `label` sets or clears the labels there.
`mashctl policy check`, `test`, `apply`, `drift` and `repair`, and the policy file, its compiler, its tests and `docs/policy-file.md` are removed; the list-set verbs that replace the file's rules come later, and `mashctl policy` has no subcommands until then (it prints its usage and exits 2). `mashctl init --local` and `adopt` no longer write a `policy.yaml`.
The `--policy` flag, the `MASH_POLICY` variable and the policy-file setting are removed from `add`, `reissue`, `retire`, `label` and `unlabel`: `--policy` is now an unknown option, and the variable is no longer read. `label --sync` is removed too, because the record is where labels live.
`mashctl add` and `mashctl reissue` refuse, before minting anything, while a zone policy of an older release is applied, or when the system credentials needed to check cannot be used, because owner-wide permissions would bypass that policy's mail restrictions.
