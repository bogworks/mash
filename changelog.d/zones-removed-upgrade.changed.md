Upgrade note: zones are removed ([ADR 0091](docs/decisions/0091-there-are-no-zones-mail-keeps-the-five-token-subject-and-the-address-is-the-fence.md)), so a directory record that still carries a zone blocks the upgrade. `mashctl audit` and `mashctl drift` report such a record as an error, and `mash serve` and `mashctl policy apply` refuse to run while one exists (`mash serve` refuses only a zoned record; it does not check for an applied policy). Run `mashctl unzone <endpoint>` for each zoned record, then upgrade: it rewrites the record to the five-token form, moves the inbox stream's subjects to the five-token mail subject without losing stored mail, and is safe to re-run; `unzone` does not reissue the endpoint's user (mash holds no user seed), so after it run `mashctl permissions <endpoint> --nsc` to reissue the user with the five-token permissions. If a zone policy is applied (zone signing keys in the account JWT), there is no migration: `mashctl policy apply` and `mashctl unzone` refuse (`unzone` needs the system credentials for its policy check, or `--no-policy-check`; verify with `mashctl audit`), and `mashctl policy apply` also refuses any policy that compiles zone constructs, the first apply included, so stay on the last release that has zones until the label policy model ships.
