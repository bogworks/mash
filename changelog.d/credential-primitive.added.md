An internal Go package, `internal/credential`, signs a credential for a public key an endpoint made for itself, for a caller that holds the account's keys: the endpoint keeps its private key, only the public half goes in, and a signed credential for the address the policy lists comes back, with the issue record written first and the same refusals the issue service gives (no policy in force, an address the policy does not list, a revoked key, a key bound to another address, a mismatched endpoint). A private key put in any field is refused and never echoed or logged. The endpoint makes its key and assembles its own creds file with two small helpers, and a report from a public key alone says what was recorded, whether the account revokes it and whether it is connected now. The direct policy driver's result now lists, for each sender the policy touches, what it needs next (a first or new credential, a rotation, or a revoke). This is an engine call with no command yet; `mashctl add` is unchanged.
