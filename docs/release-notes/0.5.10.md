### Summary

**mash 0.5.10 changes what a script reads: `--json` field names, some exit codes and some message wording. If a
script parses `mash` or `mashctl` output, read Upgrading before you install.** For a person at a terminal, both
commands now read alike: help starts with a `Usage:` line, a success is one short line, every error has one form,
and `mash inbox` shows each sender's full address. The setup skill gives you the PATH line for your shell and sends a
test note you can tell apart from your own; after a reboot, ask Claude to "start mash's server again". After an
endpoint's key is replaced, mail signed with the old key is no longer labelled verified. A 0.5.5 configuration folder
is no longer migrated: upgrade it through 0.5.9 first. The known issues are listed below.

### Upgrading

**This step is one-way:** a problem found after upgrading is fixed by the next release; you do not go back to 0.5.9.

If you only use mash from Claude Code sessions, steps 1 to 5 are all you need; the rest is for scripts.

**If you are still on 0.5.5's configuration folder,** upgrade to 0.5.9 and run its migration first. 0.5.10 no longer
carries the script or recognises that folder.

On each machine with endpoints, then on the administrator's machine, in this order:

1. **Check first:** `mash version`, `mash doctor` and, as administrator, `mashctl doctor`. Each doctor should end
   with no problem and exit 0. If one does not, fix that first with
   [troubleshooting](https://github.com/bogworks/mash/blob/v0.5.10/docs/troubleshooting.md).
2. **Install `mash` and `mashctl` 0.5.10** from the same release, with the README's install steps. Endpoints, keys
   and mail stay where they are.
3. **Update both plugins,** `mash` and `mash-setup`: `claude plugin update mash@mash` and
   `claude plugin update mash-setup@mash`. The plugin that runs the 0.5.10 program comes out shortly after the
   release. To know you have it, ask a session "which mash version is this?": it says `mash v0.5.10 (<commit>)`
   when you do, and `mash v0.5.9` until then; update again until it says 0.5.10.
4. **Restart each Claude Code session.** A running session keeps its old hooks and mail process until you restart it.
5. **Check again** as in step 1; `mash version` now says `mash v0.5.10`.

Machines at mixed versions send and read each other's mail on one server, both ways.

**If a script reads `mash` or `mashctl` output:**

- **Exit codes follow one rule:** 0 it worked, 1 it failed, 2 the command line was wrong. Five cases move from 2 to
  1: no endpoint installed, a join file that needs your seed, `mashctl endpoint delete` with no terminal, a refused
  plain `http://` URL, and a refused encryption override. An unknown flag is now `error: unknown flag --x`, exit 2.
- **`--json` names changed:** `mashctl status` gives `ready`, `endpoint_count` and `online_count` (were `ok`,
  `endpoints`, `online`); `mashctl endpoint list` and `show` give `online` and `suspended` as booleans in place of
  `state`; `capability` is now `capabilities` in `endpoint show`, and `server` is now `servers` in `mashctl init`.
  An unset field is `null`, never `""` or missing. `mash who` keeps `capability`, because other tools read its JSON
  as a fixed contract.
- **`--json` is one compact line when piped,** and indented only at a terminal. Parse it; do not match its layout.
- **Text changed:** success lines (`Mail sent (number 7 in acme.demo.alice's inbox)`), the inbox column `SENT`
  (was `WHEN`), the full sender address in `mash inbox`, and the `ADDRESS` column of `mashctl endpoint list`.
  A script that matches text should match the new lines.

### What changed

#### Added

- **`mashctl doctor`'s keys row now fails when the signing key in `config.json` is not in the key folder or not listed in the account.** Before, a lost or unlisted signing key showed only when `mashctl endpoint create` was refused ([#1288](https://github.com/bogworks/mash/issues/1288)).

#### Changed

- **Both commands read the same way, and one rule gives the exit code.** `mash --help` and `mashctl --help` now start with a `Usage:` line, explain SAP, NATS and creds in a sentence, and end with a pointer to the per-command help; a command's help lists only the options that command takes. `mashctl` help says `<address>` everywhere. `mash send` now says `Mail sent (number 7 in acme.demo.alice's inbox)`, the inbox column that read WHEN reads SENT, and `mashctl endpoint create` ends with the line to start Claude Code as the new endpoint (it names `MASH_CONFIG_DIR` when the credentials went to another folder, and `MASH_SERVER` or `MASH_CA` when you gave `--server` or `--ca`). `mash doctor` words its refused-mail and delivery rows more plainly, and the hints that pointed at nothing useful are gone. Exit codes: 0 it worked, 1 it failed, 2 the command line was wrong, in both tools. This changes five cases from 2 to 1: no endpoint installed here, a join file that needs your seed, `mashctl endpoint delete` with no terminal to type the address in, a refused plain `http://` URL, and an encryption override that is refused. `mash hook` now exits 0 for a host it does not know ([#1100](https://github.com/bogworks/mash/issues/1100)).
- **`mashctl endpoint create` prints where the credentials file is.** The text output has a `Credentials: <path>` line after `Created endpoint`, as `--json` already had in "creds" ([#1044](https://github.com/bogworks/mash/issues/1044)).
- **`mashctl endpoint delete` now says in its confirmation that mail arriving while the delete runs is lost too.** The question is otherwise unchanged ([#912](https://github.com/bogworks/mash/issues/912)).
- **`--detail` blocks and other `label: value` blocks now pad every label to the longest label in the block plus one space, so values line up and none overflows its column (`mash send --detail`, `mashctl endpoint show` and `mashctl endpoint reissue --detail`)** ([#1050](https://github.com/bogworks/mash/issues/1050)).
- **mash --help and mashctl --help now say in one sentence what SAP, NATS and creds are, and mashctl --help lists its global options and --json for every verb that has it.** [#1048](https://github.com/bogworks/mash/issues/1048), [#1100](https://github.com/bogworks/mash/issues/1100)
- **`mash inbox` prints the sender's full address in the FROM column.** It no longer shortens a sender in your own owner and group to its name, so two senders cannot print alike ([#1045](https://github.com/bogworks/mash/issues/1045)).
- Both tools' `--json` outputs show an unset field as `null` (never `""`, never left out) and name a list in the plural: `mashctl endpoint show` always has `role`, `host`, `description` and `note` and gives `capabilities` (was `capability`), `mashctl init` gives `servers` (was `server`) and `signing_key_pub` as `null` when no key is set, and `mashctl doctor` and `mash version` give `"detail": null` and `"plugin": null` in place of `""`; `mashctl`'s changing commands and `mash join` always have `dry_run` (`false` on a real run), and `mashctl init` has `would_change`, `null` unless it is a dry run; `mash who` keeps `capability`. [#1042](https://github.com/bogworks/mash/issues/1042)
- Both `--json` outputs name one fact one way: `mashctl status` says `ready`, `endpoint_count` and `online_count` (were `ok`, `endpoints` and `online`), and `mashctl endpoint list` and `show` give `online` and `suspended` as two booleans in place of the `state` word. [#1041](https://github.com/bogworks/mash/issues/1041)
- **--json output is indented on a terminal and one compact line when piped or written to a file, in both mash and mashctl.** Error objects follow the same rule ([#1043](https://github.com/bogworks/mash/issues/1043)).
- **The send kind's help says when it wakes.** blocker, question and task wake an idle session only when it has mash's wake channel on; otherwise the message arrives with its next turn ([#1179](https://github.com/bogworks/mash/issues/1179)).
- **`mashctl endpoint list` now prints the owner and group on every row and an ADDRESS column, and `--wide` shows ADDRESS in place of NAME** ([#1040](https://github.com/bogworks/mash/issues/1040)).
- **`mashctl` now accepts global options before the verb (`mashctl --json status`), and `mash` and `mashctl` both report an unknown flag, before or after the verb, as `error: unknown flag --verbose` (exit 2, only the flag's name, never a value after `=`) instead of an unknown command or `unknown option`; neither it nor an unknown command prints a hint** ([#1047](https://github.com/bogworks/mash/issues/1047)).
- **No endpoint installed: the error names the setup skill.** `mash status`, `mash doctor` and the other commands now say how to set mash up: the error names the setup skill. There is no hint line, because no single command fixes a fresh machine.
- **The send tool's description now names its two required arguments.** It says address is the recipient and message is the text, so the first call is right ([#1209](https://github.com/bogworks/mash/issues/1209)).
- **`mash` and `mashctl` now word a success, an unknown command and a missing thing alike.** A success line has a capital first letter and no full stop (`Mail sent (number 42)`, `Joined as acme.demo.bob`), `mash` says `error: unknown command "x"` with no hint as `mashctl` does, and a missing endpoint or message reads `error: no endpoint <address>` or `error: no message N` in both ([#1046](https://github.com/bogworks/mash/issues/1046)).

#### Removed

- **A 0.5.5 configuration folder is no longer migrated or named in an error.** The `mash-migrate-0.5.5.sh` script is no longer a release asset, and `mash` and `mashctl` no longer refuse a folder that still holds 0.5.5's keys; anyone with such a folder upgrades through 0.5.9 first, which still carries the script. This also removes the unchecked `curl | bash` command the old error printed ([#1446](https://github.com/bogworks/mash/issues/1446), [#1458](https://github.com/bogworks/mash/issues/1458)).

#### Fixed

- **An idle session with held mail from senders it can no longer verify no longer re-reads its whole inbox every minute.** While the held mail is unchanged, the backlog check re-reads the inbox at most every 10 minutes ([#1350](https://github.com/bogworks/mash/issues/1350)).
- **The by-hand guide shows the installer's current gh warning.** The sample output has `warning: gh not found: checked checksums only, not verified`, and the guide names the other gh warnings ([#1587](https://github.com/bogworks/mash/issues/1587)).
- **The by-hand guide says unverified mail is dropped and counted, not refused.** The sender is not told, and `mash doctor` shows the count ([#1588](https://github.com/bogworks/mash/issues/1588)).
- **`mash --version` and `mashctl --version` now print the version, the same as `version`,** where `mash` used to refuse it as an unknown command; and a malformed address is now described as `owner.group.name`, the form the rest of mash uses. [#1374](https://github.com/bogworks/mash/issues/1374)
- **A relative `MASH_CONFIG_DIR`, `MASH_STATE_DIR` or `MASH_KEYS_DIR` is refused without printing its value.** The error names the variable and says it must be an absolute path ([#1343](https://github.com/bogworks/mash/issues/1343)).
- **`mashctl endpoint delete` no longer removes a creds file that was replaced while it was being archived.** It now takes the file aside first and archives that one, so a new file at the same path is left alone.
- **A shell no longer shows unverified mail as delivered when serve's write to the session failed.** The mail is recorded as delivered only once it is written, so a failed write that is redelivered stays unshown to a shell that does not accept unverified mail ([#1507](https://github.com/bogworks/mash/issues/1507)).
- **`mashctl doctor` no longer prints a connected user's key unless it is a user key.** The key comes from the server and was printed as given. A value that is not a user key now shows as `(not a user key)`. The reference now also says what doctor does with a plain `nats://` server URL (exit 2), where its hint goes, how a missing issue store is reported, and shows all six rows in the JSON example ([#1376](https://github.com/bogworks/mash/issues/1376)).
- Troubleshooting now explains each answer of the `claude` row in `mash doctor`: below the tested Claude Code version (a failure), above the tested series, unreadable, and not found ([#1598](https://github.com/bogworks/mash/issues/1598)).
- **`mashctl doctor` handles the timing of its connection reads correctly.** A single page request that timed out was taken for doctor's own deadline, so the keys row was decided from earlier reads instead of failing. A retry could run a few seconds past the deadline. A change to one of mashctl's own connections seen while one server's pages were read could be missed, so the churn warning was not raised. All three are fixed ([#1362](https://github.com/bogworks/mash/issues/1362)). The churn rows say "wait a minute and run it again" in their text, and they have no hint, because running doctor again does not fix anything.
- **`mashctl doctor` keys lines stay within 80 columns.** A revoked key together with churn among mashctl's own users, and `--audit-users` with servers whose lists kept changing, printed lines wider than 80 columns. The warning now has a line of its own, each server has its own line, and a long server id is shortened.
- **After a session restart, mash no longer says another copy of the session holds the endpoint when that copy has already exited.** [#816](https://github.com/bogworks/mash/issues/816)
- **The disk warning of `mashctl init` counts the buckets as they are.** On a re-init over buckets whose size caps were raised earlier, the warning used the configured caps and could stay quiet on an account that was too small. It now uses the larger of each live cap and the configured one.
- **`mashctl init` no longer reports a lost connection during the account lookup as a missing account.** It now says it cannot reach the server ([#1563](https://github.com/bogworks/mash/issues/1563)).
- **`mashctl init` now refuses a key written where the setup file wants a path, whatever kind of key it is.** It caught only operator, account and user seeds (`SO`, `SA`, `SU`); it now catches every NATS seed prefix, and also checks the `servers` entries. The error names the key and never repeats the value ([#1342](https://github.com/bogworks/mash/issues/1342)).
- **The installer names every writable folder at once.** When more than one folder on the way up from the install folder was writable by its group or others, it named only the nearest, so fixing it and running again met the next. It now prints one refusal that names all of them with one `chmod go-w` command.
- **The join guide shows the output of `endpoint create --out` and of a finished retry** ([#1590](https://github.com/bogworks/mash/issues/1590)).
- The join guide now says plainly that the local setup cannot be joined from another machine, and links the page that sets up a server both machines can reach ([#1589](https://github.com/bogworks/mash/issues/1589)).
- **After an endpoint's key is replaced, mail or a prompt signed with the old key no longer shows as from that endpoint, and the old key no longer counts it as online.** Before, a session that had already read the endpoint's record kept taking the old key as that endpoint's.
- **Stopping `mash serve` with a signal just as it starts no longer leaves the endpoint name held for up to 90 seconds.** A start that is cancelled while its first lease write is in flight now gives the lease back ([#638](https://github.com/bogworks/mash/issues/638)).
- **A session that restarts its serve quickly no longer gets "already in use by another session" when the earlier serve refreshed its lease at the wrong moment.** The takeover now reads the lease once more and decides again ([#621](https://github.com/bogworks/mash/issues/621)).
- **The mash-vs-SAP page links its SAP source.** It links the SAP core protocol and the mash and SAP page instead of naming a repository ([#1596](https://github.com/bogworks/mash/issues/1596)).
- **The prompt endpoint now advertises the size it accepts, 32 KiB (`32KB`), not 1 MB.** SAP callers that trust the advertised `max_payload` are no longer refused with a 413 for a prompt between 32 KiB and 1 MB.
- **The quick start says where `bob` and `alice` live.** They are in `~/.local/bin`; if the shell says command not found, open a new terminal or add it to PATH ([#1592](https://github.com/bogworks/mash/issues/1592)).
- **The README says what happens to unproven mail.** By default it is dropped and counted (`mash doctor` shows the count), not delivered with a label; `accept_unverified` delivers it with its label ([#1586](https://github.com/bogworks/mash/issues/1586)).
- The unverified-mail refusal count is exact after a kill that follows a prune of the refused-sequence file: the file now records how many sequences it dropped, so the count is no longer left one low (#1302).
- `mashctl revoke` and the other account pushes now give each server 5 seconds, not 2, to acknowledge the update, so a loaded server no longer makes a revocation that landed report "pushed but not confirmed" ([#1522](https://github.com/bogworks/mash/issues/1522)).
- **`mash serve` now exits promptly when its session ends, even if the endpoint was deleted while the session was running.** It no longer waits on a connection that is being refused, and leaves the lease to expire ([#1477](https://github.com/bogworks/mash/issues/1477)).
- **`mash serve` now exits promptly when its session ends, even if a hook is stalled while holding the spool lock.** It no longer waits on that lock after stdin closes ([#1651](https://github.com/bogworks/mash/issues/1651)).
- **The local NATS setup script accepts a sticky folder like /tmp on macOS.** It read the folder's mode without the sticky bit, so it refused `--dir` under /tmp (mode 1777) as writable by others; it now reads the full mode, as it already did on Linux ([#1341](https://github.com/bogworks/mash/issues/1341)).
- **`mashctl status` now says when the admin credentials are not set.** It used to name the server setting as missing when it was set, report "not ok" as if the server had failed, and point to `mashctl doctor`, which could not help. It now says which setting to give.
- **The team guide says when mail wakes a session.** A `question`, `blocker` or `task` wakes an idle session only with the wake channel, and `--urgent` wakes it at once only for a verified sender, as the README says ([#1593](https://github.com/bogworks/mash/issues/1593), [#1594](https://github.com/bogworks/mash/issues/1594)).

#### Security

- mashctl endpoint reissue now reads the staged seed and the creds file through one open that refuses symlinks and files other users can read or own, so a file cannot be swapped between the check and the read. https://github.com/bogworks/mash/issues/177


### Verify your download

Every download has a build attestation; verify it before you run it, with the steps in [Verify what you download](https://github.com/bogworks/mash/blob/v0.5.10/docs/install.md#verify-what-you-download) and [Verify a release](https://github.com/bogworks/mash/blob/v0.5.10/docs/release.md#verify-a-release).

### Known issues

There are 2 known issues. Each has an issue; the issue is the place for detail and any workaround.

- **Right after an endpoint's key is replaced, mail signed with the old key can briefly still be labelled verified.** A directory read that was already under way can put the old key back until the next refresh. A fix is planned. [#1759](https://github.com/bogworks/mash/issues/1759)
- **Two installers racing into one directory can leave `mash` and `mashctl` at different versions.** Rerun the installer; it replaces both programs and checks the pair, so the split repairs. [#1578](https://github.com/bogworks/mash/issues/1578)
