### Known issues

There are 4 known issues. Each has an issue; the issue is the place for detail and any workaround.

- **A pinned plugin runs its own copy of mash, not the one on your PATH.** If a host needs a different mash, set `MASH_BIN` or use the unpinned plugin. [#1497](https://github.com/bogworks/mash/issues/1497)
- **Deleting an endpoint can, in a rare race, remove a creds file that was replaced a moment earlier.** The endpoint's key is already cancelled by then, so the replacement belongs to a deleted endpoint. [#1471](https://github.com/bogworks/mash/issues/1471)
- **The 0.5.5 migration command in the docs downloads a script and runs it without checking it first.** Use it only if you trust the network you are on; a checked download is planned. [#1458](https://github.com/bogworks/mash/issues/1458)
- **`mash doctor` cannot tell when the mash in your shell differs from the one your plugin runs.** Its tool inside Claude Code checks the plugin's own mash against itself, and from a shell it cannot see the plugin. To check by hand, run `mash version` in a shell and compare it with the `binary` row of the doctor tool. [#1535](https://github.com/bogworks/mash/issues/1535)
