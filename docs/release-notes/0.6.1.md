### Summary

**mash 0.6.1 is the same program as 0.6.0, and its release tag is now signed.** Nothing in `mash` or `mashctl` changed. If you installed 0.6.0 there is nothing to do, except that 0.6.1 is the version to install from now on.

### Upgrading

There is nothing to do if you run 0.6.0: it is the same program, so no endpoint, key or mail changes. Install `mash` and `mashctl` 0.6.1 from the same release when you next install, with the README's install steps. To check that the release tag is signed, follow [Verify a release](https://github.com/bogworks/mash/blob/v0.6.1/docs/release.md#verify-a-release).

### What changed

Nothing in the programs. The release process now signs the release tag; see [Verify a release](https://github.com/bogworks/mash/blob/v0.6.1/docs/release.md#verify-a-release).

### Verify your download

Every download has a build attestation; verify it before you run it, with the steps in [Verify what you download](https://github.com/bogworks/mash/blob/v0.6.1/docs/install.md#verify-what-you-download) and [Verify a release](https://github.com/bogworks/mash/blob/v0.6.1/docs/release.md#verify-a-release).

### Known issues

The known issues are the same as in [0.6.0](https://github.com/bogworks/mash/blob/v0.6.0/docs/release-notes/0.6.0.md#known-issues): two, each with an issue that is the place for detail and any workaround.

- **A prompt signed in the second the endpoint restarted, or sent by a sender whose clock runs ahead, can be replayed for up to about 60 seconds after the restart.** [#1829](https://github.com/bogworks/mash/issues/1829)
- **A plain shell reports a state folder mash cannot create only when the spool setting is visible to it.** [#1907](https://github.com/bogworks/mash/issues/1907)

### What is not in this release

Security policy is planned and is not in this release. Nothing else is promised here.
