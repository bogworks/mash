# mash v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `mash`, a single Go binary that is a Claude Code channel server (`mash serve`), a CLI and an admin tool, implementing SAP 0.3 plus a `mail` verb on per-endpoint JetStream inboxes.

**Architecture:**
- **Packages:** small internal packages (`config`, `sap`, `admin`, `store`, `render`, `endpoint`, `mcp`), wired by `cmd/mash`.
- **Tests:** everything that touches NATS is tested against an in-process `nats-server` in operator mode, whose users carry the exact production permissions.
- **Live run:** the reference deployment.

**Tech Stack:** Go 1.27; `github.com/nats-io/nats.go` v1.54.0 (`jetstream`, `micro`), `nkeys` v0.4.16, `jwt/v2` v2.8.2, `nats-server/v2` v2.15.1 (tests only). The standard library for everything else; no MCP SDK.

**Spec:** `docs/specs/2026-10-21-mash-design.md`.

## Global Constraints

- **Module:** `github.com/bogworks/mash`. License Apache-2.0. No deployment-specific values in code; `example.com`, `acme` and `host-a` appear only in docs and in the appendix.
- **Subjects:** `agents.{verb}.cc.{owner}.{name}`, with verbs `prompt`, `status`, `hb` and `mail`. Service name `agents`, queue group `agents`, `protocol_version` `"0.3"`, `metadata.agent` `claude-code`.
- **Name rule:** `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`, 1–48 characters. The owner uses the same rule.
- **Inbox stream `inbox-<name>`:** subjects `agents.mail.*.<owner>.<name>`, file storage, limits retention, MaxAge 30 days, MaxBytes 16 MiB, MaxMsgSize 1 MiB, DiscardOld, Duplicates 2 min, DenyDelete, DenyPurge, AllowDirect, no subject transform.
- **Consumer `deliver`:** durable pull, explicit ack, AckWait 30 s, MaxAckPending 1000, DeliverAll.
- **KV buckets:** `mash-directory` (history 1, file) and `mash-leases` (history 1, TTL 90 s, file).
- **`Agent-Sender` v1:** exactly SAP §13.5–13.6. Tag `AGENT-SENDER-V1`, seven LF-terminated lines, ed25519, base64url with no padding. `id_sig` tag `AGENT-ID-V1`.
- **Delivery defaults:** settle 100 ms; inline limits 10 messages and 16384 bytes.
- **Timing:** lease refresh 30 s; heartbeat 30 s; prompt "working" status every 30 s; prompt reply timeout 10 min.
- **Reconnect:** wait 2 s, jitter 0–5 s, unlimited attempts.
- **Secrets:** credentials files are mode 0600. Seeds are never logged, never sent as tool output, and never written outside the credentials file. mash never handles account or operator seeds.

## Review Focus

1. **The inbox consumer fails mid-delivery:** a notification is written and then the process dies. Expected: at worst redelivery, never loss. Ack only after the write. Pinned in Task 8 (`TestDeliverAcksOnlyAfterWrite`).
2. **A message that isn't valid UTF-8 or is over 16 KiB inside a small batch.** Expected: the batch becomes a digest, and invalid bytes are replaced, not dropped. Task 7 (`TestRenderInvalidUTF8`, `TestRenderOversizedSingle`).
3. **The connection drops and comes back.** Expected: the consumer resumes, the lease is refreshed or lost cleanly, and nothing is delivered twice to Claude. Task 8 (`TestReconnectResumes`).
4. **The directory changes while running:** an endpoint is deprovisioned, or a new one added. Expected: `send` to the removed name fails, `who` updates, and mail from the removed user shows as `unknown-signer`. Task 8 (`TestDirectoryLiveUpdate`).
5. **`MASH_NAME` is set but the credentials belong to another user.** Expected: `serve` refuses with a clear message and holds no lease. Task 8 (`TestIdentityMismatchRefuses`).
