# mash releases (G19): v0.1.0 as a tagged, reproducible build

**Why:** Rangehand pins mash by a bare commit (`dd2f033`, the S5 fix) because mash has no tagged releases. G19
asks for `v0.1.x` tags with a release check of mash's own, so Rangehand's `compat.json` can pin a tag and its commit.
**Model:** Rangehand's pipeline (spec §17: `scripts/release-check`, `.github/workflows/release.yml`), reduced to what
mash needs: a candidate commit X on main, built twice in fresh clones in different directories with a pinned
toolchain, byte-identical, `mash version` printing the tag. The lead pushes the signed tag; CI builds and drafts.

## Decisions

1. **Version.** `mash version` prints `mash <version> (commit <sha>)`. `<version>` is, in order: the release
   ldflag `-X github.com/randybias/mash/internal/endpoint.Version=<v>` (CI and the check set it), else the module
   version of a `go install …@v0.1.0` build (`debug.ReadBuildInfo` `Main.Version`, minus the `v`), else `dev`.
   `main` also sets `endpoint.Version` to it, so the SAP service version matches. `<sha>` as today (ldflag
   `main.commit`, else `vcs.revision`).
2. **One build recipe**, `scripts/build-release <src> <out> <goos> <goarch> <version> <commit>`, used by the
   workflow and the check, so they cannot differ: `GOTOOLCHAIN=go1.27.3 CGO_ENABLED=0 go build -trimpath
   -buildvcs=false -mod=readonly -ldflags "-X …Version=<v> -X main.commit=<sha>" ./cmd/mash`; prints the SHA-256.
3. **`scripts/release-check <commit> <version> [--all] [--no-ci]`** (bash): X is a full 40-hex sha reachable from
   `origin/main`; version is `N.N.N`; CI check runs on X named `test (ubuntu-latest)`, `test (macos-latest)` and
   `reproducible` are all `success` (via `gh api`; `--no-ci` skips with a loud warning, for use without auth); the
   host target (all four with `--all`) is built twice in two fresh clones of X in different directories and the
   SHA-256s must match; the host binary's `version` must print the exact line. It prints each SHA-256 and the
   `compat.json` snippet (`{"version", "commit"}`), and exits non-zero on any failure.
4. **`.github/workflows/release.yml`** on tag `v*`: tag is annotated and signed (shape), X is on main, then per
   target (linux/darwin × amd64/arm64) two fresh-clone builds that must match, upload; a `draft` job writes
   `SHA256SUMS` and a changelog from `git log` since the previous tag, and creates a **draft** release.
5. **CI** (`ci.yml`) gains a `reproducible` job: the same two-clone build on every push and PR, so a change that
   breaks reproducibility fails before a tag does. `go test ./...` includes a test that runs the build recipe twice
   on HEAD and asserts equal bytes and the version line.
6. `docs/release.md` is the procedure. Tagging stays the lead's; this work does not tag.

## Tasks (test-first, Codex on each diff)

1. **Version resolution** (`cmd/mash/main.go`, `main_test.go`): `resolveVersion`; table test (ldflag wins; module
   version; `(devel)` and empty give `dev`); `mash version` end to end with the ldflag via a built binary.
2. **`scripts/build-release` and the reproducibility test** (`scripts/release_test.go`): two builds of HEAD in
   different directories give equal SHA-256; the binary prints the version line; different commit or version gives a
   different binary.
3. **`scripts/release-check`**: tests drive it against a throwaway repo with a fake `origin/main`: refuses a commit
   not on main, a short sha, a bad version; passes with `--no-ci`; refuses without `--no-ci` when `gh` is absent;
   the printed compat snippet is exact.
4. **Workflows** (`release.yml`, `ci.yml` job): a test parses the YAML and asserts the pins (GOTOOLCHAIN, CGO
   off, `-trimpath`, both clones, the tag guards, draft only); no job writes outside `contents: write` in `draft`.
5. **`docs/release.md`**, README install note (`@v0.1.0`), and a dry run of `release-check --no-ci` at HEAD.

## Review Focus

- Reproducibility leaks: build paths, `-buildvcs`, the module cache path, timestamps, `GOFLAGS`, `GOROOT`, cgo.
- The release check trusting the tag name instead of the commit (it must bind version to X).
- A lightweight or unsigned tag producing a draft; a tag on a commit not on main.
- `compat.json` pinning a commit that is not the one the tag points at.
