# Live end to end, 2026-10-22

- **Setup:**
  - Reference deployment: NATS 2.14.6 on devsup1, over `tls://nats.thaos.dev:4222`, account `MASH`, owner `randyb`.
  - Client: plethorax (macOS), Claude Code 2.1.306–2.1.307 (Claude Max).
  - mash 0.1.0 at commits `0ea211d` to `d71f4f3`.
- **Install:** the plugin was installed from the local marketplace (`claude plugin marketplace add ~/code/mash`, local scope in a scratch folder). The managed-settings allowlist was `{"marketplace":"mash","plugin":"mash"}`.
- **Launch:** `MASH_NAME=<n> claude --channels plugin:mash@mash`.

## Setup on the account

| Step | Result |
|---|---|
| Raise MASH limits: streams 64, consumers 128, no memory store | Pushed. The server earlier refused a 64 MB memory reservation (it has no memory store), so mash uses file storage only. |
| Remove the proof of concept's `MAIL` stream | Removed. The account had no streams afterwards. |
| `mash admin init` | `mash-directory` and `mash-leases` (90 s TTL) created. |
| Mint `mash-alpha` and `mash-beta` | Minted with `nats-operator.sh add-user MASH <n>`, using the flags from `mash admin permissions <n> --nsc`. Each JWT carries 20 publish and 5 subscribe permissions, and responses up to 1000 messages for 15 minutes. |

**Incident during setup.** The first mint ran under zsh, which has no `mapfile`, so the permission flags were empty and both users were issued with **no permissions**, which means full account access. Their credentials existed only on plethorax, at mode 0600, and were never used. Both users were revoked (revocations pushed), deprovisioned, and their seeds purged. They were then re-minted under bash by a script that refuses to proceed unless the user carries more than 10 publish permissions.

## Model speed: Opus 5.5 compared with Haiku 5.5 (2026-10-22)

The same `mash-beta` session setup was launched with the default model (Opus 5.5) and then with `--model claude-haiku-5-5`, and `speed-trials.sh` was run from the shell as `mash-alpha`. A live prompt asks for a one-word answer with the reply tool. A mail trial asks the receiver to reply with its send tool; the script then polls the CLI inbox every 0.25 s, which adds up to about 0.9 s.

| Trial | Opus 5.5 | Haiku 5.5 |
|---|---|---|
| Live prompt 1 (first turn in the session) | 10,428 ms | 4,379 ms |
| Live prompt 2 | 4,051 ms | 2,220 ms |
| Live prompt 3 | 3,850 ms | 2,382 ms |
| Mail round trip 1 | 6,180 ms | 4,266 ms |
| Mail round trip 2 | 6,378 ms | 3,420 ms |

- **The floor:** a one-shot `mash send` takes 511–540 ms, for process start, the TLS connect, the directory load, the publish and the ack.
- **Where the time goes:** of a warm Haiku prompt (about 2.2 s), roughly 0.6 s is the CLI and discovery and about 1.6 s is the model's turn; for Opus the turn is about 3.3 s.
- **Correctness:** both models answered every trial correctly, without asking for confirmation.
- **Side note:** `mash who` takes about 2.7 s because presence waits the full 2 s for discovery answers.
